Mockups: every screen and state

This page holds the information architecture, the key flow from first launch to the end of a session, and high-fidelity frames for every screen and state in Arabic and English, light and dark, at 360×800 dp. The frames are built only from the Phase 1 tokens you approved, Readex Pro, and the logo files. The copy table, the view-model changes and the open questions follow the frames.

Decisions for this review
  1. The request screen puts Accept and Reject after the consequence, at the end of the content, so they are not pinned. You reach the buttons only by passing what accepting means.
  2. Accept and Reject use the same outlined style, side by side, each with an icon (✕ and ✓). Invitations get the same treatment with Decline and Accept.
  3. "End the session now" is a filled teal button, not red. Ending is the safe action, and red would make it feel dangerous.
  4. A reconnect shorter than 5 s shows "Getting ready…" instead of "Requests can't reach you".
  5. Turning "without asking" on asks for confirmation in a bottom sheet; turning it off is immediate.
  6. "No internet" has no button. Opening Wi-Fi settings would need a new platform call; say if you want one.
  7. The launcher label follows the phone's language (Josour or جسور) through a values-ar Android string. The in-app switch stays as it is.

Structure

There are two tabs, one full-screen takeover, two confirmation sheets and the system surfaces. The tab bar has room for a third tab when the phone can also be a guest.

Signed out

  • Splash (system) → Starting (restoring the stored sign-in)
  • Sign-in: lock-up, server, email, password, language; error, busy, signed-out reason

Tab 1 · Share (home)

  • Status hero: Off · Connecting · Ready · Unreachable · No internet · Needs attention · In session · Ended
  • Available toggle (in the hero)
  • Invitations-waiting banner
  • Your connection: network, server, address sites see, mobile-data and VPN warnings
  • How sharing works (expandable)
  • Use someone else's connection (the guest-role note)
  • Account: email, language, sign out → sheet

Tab 2 · Contacts (badge = invitations)

  • Invitations to you (Decline / Accept)
  • Contacts: presence, email, "without asking" toggle → sheet when turned on, Remove → inline confirmation
  • Invite someone: field, feedback
  • Invitations you sent (Waiting / Expired, Withdraw)
  • Loading and empty states

Tab 3 · Use a connection (later)

  • Not designed here: placement only. It appears when the guest role ships (proposal doc, phase 2), and the Share tab's note announces it until then.

Over everything

  • Incoming request: full screen, from any tab or from the notification; countdown; Reject / Accept; expired state

System

  • Launcher icon (adaptive, themed), splash
  • Foreground notification: available (Stop sharing) / in session (countdown, End)
  • Request heads-up → request screen
  • Invitation → Contacts tab
  • Auto-accepted, signed-out notes

Accessibility, RTL and Android details carried into Phase 3

TalkBack

  • AutomationProperties.Name on every interactive element: the toggle ("Available for requests"), the eye button, tabs, the badge ("Invitations waiting for your answer: 1"), the countdown and End now.
  • The hero has LiveSetting=Polite, so a state change is announced once. The request heading and the sign-in error are Assertive.
  • When the request takeover opens, focus moves to its heading, and reading order follows the visual order.
  • Back on the takeover leaves the decision for later: the request stays on screen until it expires.

Size and contrast

  • Touch targets are at least 48 dp, and fields are 52 dp tall.
  • Every text pair uses the approved token pairs (≥ 4.5:1), and borders and icons are ≥ 3:1.
  • At 200% font size text wraps and nothing is clipped (frames below). Only the hero's countdown digits stay on one line.
  • Warnings always pair an icon shape with words, never colour alone.

RTL

  • Arabic mirrors the layout, the switch thumb, the tab order and the sign-out arrow.
  • The symbol and motif never mirror. Only which dot is "you" follows the reading start.
  • Emails, URLs, IPs, device names, times and sizes are wrapped in Tr.Ltr, and LTR fields align their text with the label side.
  • Western digits in both languages, as today.

Android resources

  • mipmap-anydpi-v26/ic_launcher.xml and ic_launcher_round.xml: background @color/josour_teal, foreground and monochrome are a 108 dp vector with the symbol path at translate(24, 18.375) and scale 2.5. minSdk 26 means no PNGs are needed.
  • drawable/ic_stat_josour.xml: the symbol path, 24 dp, white.
  • values, values-night and values-v31 styles for window and bar colours and the splash attributes; values-ar/strings.xml for app_name.

Notifications

  • SetColor(#0E7490) on every notification.
  • In a session the notification uses a countdown chronometer (SetUsesChronometer, SetChronometerCountDown, SetWhen = the end time), so Android counts it down with no per-second updates. Data used is refreshed with each stats update, as today.
  • The request notification keeps no Accept action, by design. No full-screen intent (decision 7).

Not changed

  • Networking, tunnel and egress code.
  • The desktop app, its icons, and the admin dashboard. The follow-ups are listed in Phase 1.
  • The real install in ~/Library/Application Support/Josour: tests and runs use the emulator only.
