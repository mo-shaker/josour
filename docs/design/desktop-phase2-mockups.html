Josour for Windows and macOS · Phase 2 of 4 · for review

Mockups: every window and state

Every desktop window in every state the brief names, in Arabic and English, light and dark, inside a Windows 11 frame or a macOS frame. The frames are HTML built only from the approved tokens (phone tokens plus desktop-tokens.json), Readex Pro, the logo files and the real resx strings, so the words are the ones the app will show. The copy table, the view-model additions and the platform surfaces (tray, menu bar, menus, notifications) follow. The 14 Phase 1 decisions were approved on 2026-11-06 and are applied throughout.

5 small decisions for this review
  1. Reuse the phone's words. The desktop reads 33 keys the phone shipped in v2.6.0 (hero titles, consequence, trust confirmation, show password and more), unchanged, so both apps speak alike. They keep their Mobile prefix: renaming them would touch the phone for no gain. The alternative is copying them into Desktop* keys, two copies that drift.
  2. Data used keeps "sent · received" on the desktop. There is room for both numbers, and the existing string stays. The phone shows one total.
  3. Sign out lives on the "This device" tab as well as in the ⋯ menu (Windows) and the app menu (macOS), always confirmed.
  4. Disabling an account asks first. The always-open red warning in User management becomes the confirmation's text (a view-model addition).
  5. The tray icon's click. On Windows a left click opens the window and a right click the menu, as today. On macOS a click opens the menu, the menu-bar convention, with "Show window" first. To check on a real Mac: what Avalonia does today when an item has both a menu and a click handler.

Structure

One main window that stays small, a request window over everything, and the system surfaces. Settings, About and User management are their own windows, opened from the ⋯ menu on Windows and from the app menu on macOS.

Main window (460×680)

  • App bar: lock-up · ⋯ (Windows)
  • Status hero: Off · Getting ready · Ready · Can't reach the server · Needs attention · Session (host or guest) · Ended
  • Tab Contacts: session length, waiting card, invitations to you, contacts (use, offer, without asking, remove), invite someone
  • Tab This device: your connection (server, device, VPN, firewall, simulated), how sharing works, account and sign out

Over everything

  • Incoming request: topmost, countdown, Accept / Reject, expired
  • In-window dialogs: without asking, remove, sign out, quit, disable an account

Windows of their own

  • Sign in · First run (3 steps)
  • Settings · About · User management · Licences
  • Start-up failed (theme-free)

System

  • Windows: tray icon (4 states) and menu, toasts, .ico, installer
  • macOS: menu-bar template image (4 states) and menu, app menu, notifications, .icns

VPN and simulated server never take the hero (warnings 3 and 4 of Phase 1). They are rows on the "This device" tab.

The same windows on both systems

The main window, the request and sign-in in a Windows 11 frame and a macOS frame. The frame (title bar, caption buttons, traffic lights) is drawn by the system in the system's language, so it is shown left-to-right even around Arabic content; only the content mirrors. Note the button order: on Windows the primary button comes first, on macOS last; Arabic mirrors both.

Every window and state

Use the System switch above for the Windows or macOS frame. Empty, loading, error, not connected, session active and request expired are all here, plus the confirmations.

Tray, menu bar, menus and notifications

The tray and menu-bar menus are native menus: the system draws them in its own style and colours, so only the words, the order and the icon are Josour's. The ⋯ menu is Josour's own (an Avalonia flyout on tokens). The first, greyed line of the tray menu says the state in words, so the icon never carries it alone.

Accessibility, keyboard and platform details for Phase 3

Screen readers (Narrator, VoiceOver)

  • AutomationProperties.Name on every icon button (⋯ "More", the eye "Show password" / "Hide password"), on the Available switch and on each contact's "without asking" switch (with the contact's name).
  • The hero has LiveSetting=Polite: one announcement per state change. The request heading, the sign-in error and the expired state are Assertive.
  • When the request window opens, focus goes to its heading; reading order is the visual order.
  • Field labels are tied to their fields (LabeledBy).

Keyboard

  • Tab order follows reading order in both directions; the focus ring (2 px, focus) shows on keyboard focus only.
  • Ctrl/⌘ , Settings · Ctrl/⌘ W close to tray / menu bar · ⌘ Q quit (asks while sharing) · Esc cancels every dialog and means "decide later" on a request.
  • Enter is the default button in Settings, sign-in and dialogs, never on the request window.
  • Arrow keys move between the two tabs.

Size, DPI and contrast

  • Controls 32 px, request buttons 40 px, pointer targets at least 24 px.
  • Every text pair uses an approved token pair (≥ 4.5:1); borders, icons and the focus ring ≥ 3:1.
  • Headless renders at 100%, 150% and 200% in Phase 4, checking that Arabic is never clipped.
  • Status always has a word and an icon shape, never colour alone.

RTL

  • The content mirrors; the system's frame does not (it follows the system language).
  • Only directional glyphs mirror (sign-out, chevron) through UiFlow.GlyphMirror; the motif and symbol never do. Only which dot is "you" follows the reading start.
  • Emails, URLs, IPs, device names, versions and sizes are bidi-isolated and stay left-to-right; LTR fields align with their label's side.
  • Western digits in both languages, as today.

Not changed

  • Networking, the tunnel, egress, the system proxy and the protocol.
  • The phone: no shared string value changes, and its code is untouched until the Josour.Brand step of Phase 3 (decision 1), where its tests must stay green.
  • The real install in ~/Library/Application Support/Josour: nothing here ran the app.
