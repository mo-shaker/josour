Josour for Android · Phase 1 of 4 · for review

Brand foundation and UI audit

The phone's UI rebuilt around the qantara mark: colour, type, shape, motif rules, the app icon and the tokens, all derived from the files in 1-qantara/. The audit of today's screens is at the end. Nothing in the app has changed yet.

Seven decisions I need from you before Phase 2

  1. Font. Readex Pro for all UI text, Arabic and Latin. It is the wordmark's own typeface (measured match below). Noto Naskh Arabic UI is removed.
  2. Launcher icon. Option B: a white symbol on a teal background.
  3. Lock-up on dark surfaces. A one-colour white lock-up, made only by changing the fills of the supplied files to #FFFFFF, the white already used in symbol-white.svg. The other option is to show only the symbol in dark mode.
  4. Status hero. It may show the arch partly drawn or with a gap to show a state. It is an illustration made from the symbol's geometry and is never presented as the logo.
  5. Semantic hues. Bluish green, amber, vermilion and blue. Each is always paired with its own icon shape.
  6. Corporate wording. Add new Mobile* keys where the phone needs different words. Edit a shared key only where the desktop benefits equally.
  7. Background requests. Keep today's heads-up notification and show the full-screen takeover when the app is opened, or ask Android for a full-screen intent. Android 14 restricts that permission to calling and alarm apps, so the user would have to grant it.

Shown from the files as they are, byte for byte. One path draws the arch and the two dots: a half-ring with outer radius 9 and inner radius 6 on a 24-unit grid, resting on two dots of radius 2.25. Why a white lock-up for dark mode: the ink wordmark (#14232B) has 1.1:1 contrast on the dark canvas, so it cannot be read. The teal symbol reaches 3.56:1, which passes as a graphic but looks dim. The lock-up is never put on a "light plate" in dark mode, which would be adding an effect to the logo.

Colour

Built in OKLCH from the logo's two colours. Teal 700 is exactly #0E7490, at hue 223°. Ink 900 is exactly #14232B, at hue 232°. The neutrals lean slightly towards the ink's blue-teal, and the light canvas has a faint teal tint so cards in pure white lift off it. In dark mode the brand teal is too dark for text (3.56:1), so the dark primary is a lighter teal, #5ECCE4, on the same hue line.

Typography

The wordmark is outlined, so I measured it. Each candidate font was shaped with HarfBuzz, rasterised and laid over the lock-up's outlines, and scored as the shared area divided by the total area (1.0 means identical). Variable fonts were scanned across their weight axis in steps of 20.

“Josour”, lock-up outline (grey) against each font (stroke)

“جسور”, lock-up outline (grey) against each font (stroke)

Finding: the wordmark is Readex Pro

"Josour" is Readex Pro Medium (weight 500) at 72 px, a 0.998 match with an identical cap height of 50.4. "جسور" is Readex Pro at weight about 560, set 1.08× larger than the Latin to balance it optically (0.994 match). Alexandria comes closest of the others on Latin (0.76) but not on Arabic (0.30). IBM Plex Sans Arabic is a different design (0.40 and 0.31).

Proposal: Readex Pro for all UI text, Arabic and Latin

  • Same voice as the logo. One family covers both scripts, with a matched x-height, so mixed lines like "بيانات الجوال · Wi-Fi" or an email inside Arabic sit on one rhythm.
  • Made for reading. Readex Pro extends Lexend, which was designed for reading fluency. Its counters are open and its Arabic letterforms simple, which suits the older, non-technical readers this app is for.
  • Licence. SIL OFL 1.1, compatible with bundling in an Apache-2.0 app. The reserved font name is "RevReading Lexend", so static instances may keep the name Readex Pro. OFL.txt ships next to the fonts, as it does today.
  • Avalonia. Avalonia 11 does not reliably select instances of a variable font from FontWeight. I'll bundle four static instances cut from the variable file with fontTools: Regular 400, Medium 500, SemiBold 600 and Bold 700, about 150 KB each.
  • Noto Naskh Arabic UI is removed. The app has no long-form text where a Naskh would read better, and two Arabic voices on one screen (a geometric lock-up over Naskh body text) look like two products. It stays a possible addition if long help pages ever arrive.

Type scale

Sizes are in dp (sp for text, so Android's font size setting applies). Arabic uses the same sizes with taller line heights, about 1.6–1.75 for body text against 1.5 for Latin, and never letter-spacing. Latin also has no tracking: Readex Pro is already wide. The lock-up's 1.08× Arabic boost is a display correction and stays in the lock-up only.

The UI stays mostly flat. In light mode, depth comes from soft ink-tinted shadows. In dark mode there are no shadows; depth comes from lighter surfaces with a border. Avalonia's BoxShadow covers all of these.

UI icons

  • 24 dp grid with a 20 dp live area.
  • 2 dp stroke, ⅔ of the logo's band at the same scale (3/24). Icons always read lighter than the mark, and the full 3/24 weight is kept for the motif.
  • Round caps and joins, from the dots and the round band.
  • Points are solid dots of 2.25 radius, the symbol's own dot (the Wi-Fi dot above).
  • Mirror in RTL: sign-out, chevrons, back. Never mirror: the symbol, clock, check, Wi-Fi, signal, battery, data arrows.
  • No shields, padlocks as a hero, masks, incognito glasses or globes with arrows. That imagery says "VPN" or "anonymous", which this app is not.

The arch as a motif

One place carries the motif with meaning: the status hero at the top of the Share tab. It answers one question: can a request reach me right now, and if not, what do I do? The dot at the start of the reading direction is you; the other is a contact. In Arabic that is the right-hand dot. Only which dot is filled follows the direction. The symmetric drawing itself never mirrors. Animation is limited to stroke offset and opacity, and stops under reduced motion.

The state is always spelled out in the title, with an icon for the problem states. The arch's colour only reinforces it. "Needs attention" names the one thing to fix, with its button (Allow notifications, Allow background use, Open Wi-Fi settings).

The arch may appear

  • In the status hero on the Share tab, in the six states above.
  • On the splash and "Starting" screen: the symbol, centred, unchanged.
  • On the sign-in screen: the lock-up for the current language.
  • In the contacts empty state: the motif with both dots hollow ("no one to connect with yet").
  • In the incoming-request header: two filled dots with the arch drawn as a dashed outline. The bridge is offered, not yet built.
  • As the Share tab's icon, in the 2 dp UI-icon style. This is the motif, not the logo.

It must not

  • Be decoration: no background patterns, watermarks, tiles or crops.
  • Spin as a loading indicator, or be rotated, mirrored, stretched or skewed.
  • Take a semantic colour, such as a red arch for an error. Problem states use the neutral arch plus an icon.
  • Sit next to VPN, shield, lock or globe imagery, or be used as a button icon for "connect".
  • Get shadows, gradients, glows or outlines, as the logo or as the motif.
  • Appear more than once on a screen, or in error dialogs and toasts.

App icon, monochrome icon, notification icon, splash

The adaptive icon canvas is 108 dp, and launchers crop it to shapes that always include the central 66 dp circle. The symbol is scaled 2.5× (19.5 × 16.5 units become 48.75 × 41.25 dp) and centred on its bounding box. Its farthest point, the outer edge of a dot, is 29.6 dp from the centre, inside the 33 dp safe radius with 3.4 dp to spare.

Option A: teal on light

Calm, but it disappears among the many white icons on a home screen, and on a light wallpaper the shape of the icon has no edge.

Option B: white on teal Recommended

Recognisable at a glance, 5.36:1 symbol contrast, a clear edge on any wallpaper, and the same teal as the notification accent and the splash. This is the decision-2 option.

What this sets up for Phase 2 and 3

One state for the hero (a small view-model change, proposed now)

The hero needs one answer instead of today's four overlapping flags (IsReady, IsUnreachable, StatusText, ShowNotificationsOffWarning). The proposal is a computed HostStatus on HostViewModel with the values Off, Connecting, Ready, Unreachable, InSession and NeedsAttention. It is derived only from properties the view model already has (IsAvailable, the channel state, IsAnnounced, HasSession, network kind, permissions), so no networking code changes. It also separates "connecting" (a short wait) from "unreachable" (a failure), which today look the same.

Room for the guest role

The tab bar becomes Share · Contacts · Use a connection. The third tab is shown only when the guest role ships (docs/android-app-proposal.ar.md, phase 2). Until then the "guest role" note on the Share tab is where it is announced. Phase 2 marks the slot without designing it.

Out of scope here: desktop follow-ups for the new logo

  • Josour.App's window and tray icons, the .ico and .icns files, and the installer artwork.
  • The admin dashboard's favicon and header.
  • README and docs screenshots.
  • Shared-key wording edits (above) also change the desktop; I'll list each one.

Method notes

  • The font match used HarfBuzz shaping and fontTools outlines, scored on 200 px-tall rasters.
  • The colour ramps are OKLCH, with chroma reduced only to stay in the sRGB gamut. Contrast is the WCAG 2.x relative-luminance ratio.
  • Colour-blind simulation uses the Machado (2009) matrices at severity 1.0.
  • The notification icon was rasterised from the exact geometry at 16× supersampling, then downsampled.
