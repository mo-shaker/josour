# قائمة القبول: معايير نجاح الإصدار الأول (18 بندًا)

مصدر البنود: القسم 16 من وثيقة المنتج. تُنفَّذ على جهازي Windows (أحدهما Windows 10) في شبكتين مختلفتين ضد بيئة staging ثم الإنتاج. لكل بند: النتيجة، التاريخ، المنفّذ، ولقطة شاشة أو سجل.

| # | المعيار | طريقة التحقق | النتيجة |
|---|---|---|---|
| 1 | تثبيت البرنامج على جهازي Windows | المثبّت الموقّع على Win10 وWin11 بلا تحذير SmartScreen؛ قاعدة Firewall تظهر في `wf.msc` | |
| 2 | تسجيل دخول الطرفين | دخول ناجح من الجهازين؛ صف `devices` لكل منهما | |
| 3 | ظهور المضيف بوصفه متاحًا | تفعيل «متاح» على المضيف ← يظهر في قائمة المستخدم خلال ثانيتين مع شارة قابلية الوصول | |
| 4 | إرسال طلب الاتصال | المستخدم يختار المضيف والمدة ← نافذة الطلب تظهر على المضيف بالاسم والجهاز والمدة والمواقع والتنبيه | |
| 5 | قبول أو رفض الطلب | الرفض يعيد رسالة للمستخدم؛ القبول ينشئ جلسة؛ انتهاء 60 ثانية بلا رد يغلق النافذة | |
| 6 | إنشاء قناة اتصال بين الجهازين | `session.connected` خلال 10 ثوانٍ؛ `sessions.winner_type` و`tls_version` مسجلان | |
| 7 | تشغيل متصفح العمل | نافذة Chrome/Edge بـ Profile مستقل تفتح على صفحة الفحص | |
| 8 | مرور المواقع المحددة عبر المضيف | صفحة الفحص تعرض IP المضيف؛ `ifconfig.me` داخل متصفح العمل = IP المضيف | |
| 9 | ظهور عنوان IP الخاص بالمضيف | `whatismyipaddress.com` في متصفح العمل = IP المضيف؛ في متصفح المستخدم العادي = IP المستخدم | |
| 10 | عدم تأثر بقية تطبيقات المستخدم | Teams/Outlook والمتصفح العادي تعمل بـ IP المستخدم أثناء الجلسة؛ لا تغيير في إعدادات Proxy النظام | |
| 11 | قطع الاتصال من أي طرف | زر القطع على المضيف يغلق متصفح المستخدم خلال 5 ثوانٍ؛ والعكس من المستخدم | |
| 12 | إنهاء الجلسة تلقائيًا عند انتهاء مدتها | جلسة 15 دقيقة تنتهي بـ `expired` ± 5 ثوانٍ ويُغلق المتصفح | |
| 13 | استعادة إعدادات المتصفح بعد الإنهاء | لا Proxy في إعدادات النظام؛ فتح Chrome العادي لا يظهر «لم يُغلق بشكل صحيح» | |
| 14 | تسجيل بيانات الجلسة الأساسية | صف `sessions` كامل: الأوقات، السبب، البايتات؛ `session_domains` عند تفعيل `log_domains` | |
| 15 | منع المستخدم من الوصول إلى جهاز المضيف أو شبكته المحلية | من متصفح العمل: `http://192.168.1.1`، `http://localhost`، `http://[::1]`، وIP المضيف العام كلها مرفوضة (403) | |
| 16 | عدم مرور بيانات التصفح عبر FastAPI | `iftop`/`docker stats` على الخادم لا يظهر زيادة أثناء تشغيل فيديو في متصفح العمل | |
| 17 | استمرار Native WebSocket طوال فترة تشغيل التطبيق | التطبيق يعمل 8 ساعات؛ `presence.connected=true` طوال الوقت؛ إعادة الاتصال بعد قطع الشبكة 30 ثانية | |
| 18 | عمل النظام من خلال VPS صغير منخفض التكلفة | الإنتاج على 1 vCPU / 2 GB؛ CPU < 20% وRAM < 60% مع 20 عميلًا متصلًا | |

## فحوص أمنية إضافية (من القسم 14 من الوثيقة)

| الفحص | الطريقة | النتيجة |
|---|---|---|
| المستمع لا يقبل غير TLS ويقطع بلا مصادقة | `nmap -sV` على منفذ المضيف أثناء نافذة الاتصال؛ `openssl s_client` ثم إرسال بايتات عشوائية ← إغلاق | |
| حذف مفاتيح الجلسة | `select count(*) from session_keys` = 0 بعد الإنهاء؛ `certutil -user -key` بلا حاويات متراكمة | |
| لا محتوى تصفح في السجلات | grep في سجلات الخادم والعميل: لا URL ولا رؤوس HTTP | |
| سياسة Proxy مؤسسية | تفعيل `ProxySettings` عبر Registry ← الجلسة تنتهي بـ `browser_not_proxied` | |
| قفل الحساب وتحديد المعدل | 10 محاولات خاطئة ← 423؛ 6 طلبات في دقيقة ← 429 | |
| الإنهاء المركزي | `POST /admin/sessions/{id}/terminate` يغلق النفق والمتصفح خلال 5 ثوانٍ | |
